## 1. 项目总体心智模型

AStudy 当前由两个相互关联但职责独立的系统组成：

1. **TRD Agent Platform**：完成 TRD 输入、结构化提取、IR 审核、目标文件生成、校验与发布。
2. **AVF Automated Validation Framework**：完成环境准备、服务启动、自动测试、证据收集和报告生成。

```mermaid
flowchart TB
    User[用户 / 开发者]

    subgraph Product[TRD Agent Platform]
        Input[TRD 与参数输入]
        Parse[AI / Tool 数据提取]
        IR[结构化中间文件 IR]
        Review[用户审核与修订]
        Generate[候选文件生成]
        Validate[规则 / Tool / AI 校验]
        Final[最终文件发布]

        Input --> Parse --> IR --> Review --> Generate --> Validate --> Final
    end

    subgraph Test[AVF 自动化自检平台]
        Bootstrap[Windows 一键启动]
        Environment[环境与依赖自检]
        Service[测试服务生命周期]
        Cases[环境 / API / Workflow / UI 测试]
        Evidence[日志与证据采集]
        Human[人工 HTML 报告]
        AIReport[AI 诊断 ZIP]

        Bootstrap --> Environment --> Service --> Cases --> Evidence
        Evidence --> Human
        Evidence --> AIReport
    end

    User --> Input
    User --> Bootstrap
    Cases -.验证.-> Product
```

## 4. FastAPI 启动流程

```mermaid
sequenceDiagram
    participant User as 用户 / Uvicorn
    participant Main as app.main
    participant FastAPI as FastAPI
    participant DB as Database
    participant Router as API Routers

    User->>Main: uvicorn app.main:app
    Main->>FastAPI: 创建 FastAPI Application
    Main->>Router: 注册 /api/v1/modules
    Main->>Router: 注册 /api/v1/runs
    FastAPI->>DB: lifespan 启动时 init_db()
    DB-->>FastAPI: 数据表初始化完成
    FastAPI-->>User: Application startup complete
    User->>FastAPI: GET /health
    FastAPI-->>User: status=ok
```

### 4.1 为什么 Uvicorn 能在手动 init_db 失败时启动

`python scripts/init_db.py` 可能因为 Python 导入路径不正确而失败，但 FastAPI 的 lifespan 仍会在服务启动时调用 `init_db()`。因此：

```text
手动脚本失败
≠
应用启动一定失败
```

后续建议统一使用：

```powershell
python -m scripts.init_db
```

或先执行：

```powershell
pip install -e .
```

## 6. Run 状态机

```mermaid
stateDiagram-v2
    [*] --> CREATED
    CREATED --> INPUT_VALIDATING
    CREATED --> CANCELLED

    INPUT_VALIDATING --> CLASSIFYING
    INPUT_VALIDATING --> FAILED

    CLASSIFYING --> EXTRACTING
    CLASSIFYING --> FAILED

    EXTRACTING --> IR_VALIDATING
    EXTRACTING --> FAILED

    IR_VALIDATING --> WAITING_FOR_USER_REVIEW
    IR_VALIDATING --> REPAIRING
    IR_VALIDATING --> FAILED

    WAITING_FOR_USER_REVIEW --> GENERATING
    WAITING_FOR_USER_REVIEW --> CANCELLED
    WAITING_FOR_USER_REVIEW --> REJECTED

    GENERATING --> VALIDATING_OUTPUT
    GENERATING --> FAILED

    VALIDATING_OUTPUT --> PUBLISHING
    VALIDATING_OUTPUT --> REPAIRING
    VALIDATING_OUTPUT --> WAITING_FOR_APPROVAL
    VALIDATING_OUTPUT --> FAILED

    REPAIRING --> EXTRACTING
    REPAIRING --> GENERATING
    REPAIRING --> WAITING_FOR_APPROVAL
    REPAIRING --> FAILED

    WAITING_FOR_APPROVAL --> GENERATING
    WAITING_FOR_APPROVAL --> PUBLISHING
    WAITING_FOR_APPROVAL --> REJECTED

    PUBLISHING --> COMPLETED
    PUBLISHING --> FAILED

    COMPLETED --> [*]
    FAILED --> [*]
    CANCELLED --> [*]
    REJECTED --> [*]
```

### 6.1 状态机解决的问题

```text
禁止 CREATED 直接变为 COMPLETED
禁止未生成 IR 就执行 Generate
禁止同一个完成任务被无限重复执行
明确失败、取消、拒绝和人工等待状态
为重试、恢复和审计提供基础
```

## 16. Validation Pipeline

```mermaid
flowchart LR
    Candidate[Candidate Artifact]
    Candidate --> Integrity[文件完整性]
    Integrity --> Syntax[语法 / 可解析性]
    Syntax --> Schema[JSON / XML Schema]
    Schema --> Business[业务规则]
    Business --> Tool[Tool / Simulator]
    Tool --> Semantic[AI 语义一致性]
    Semantic --> Aggregate[Finding 聚合]
    Aggregate --> Decision{质量门禁}

    Decision -- 通过 --> Publish[允许发布]
    Decision -- 不通过 --> Repair[自动修复候选]
    Decision -- 不通过 --> Review[人工处理 / Waiver]
```

### 16.1 确定性校验与 AI 校验边界

```mermaid
flowchart TB
    Validation[Validation]

    Validation --> Deterministic[确定性校验]
    Validation --> Semantic[AI 语义校验]

    Deterministic --> D1[必填字段]
    Deterministic --> D2[类型 / 枚举 / 范围]
    Deterministic --> D3[唯一性 / 引用完整性]

```

原则：**能够使用确定性规则验证的内容，不应只交给 AI 判断。**

## 25. Memory 自学习闭环

```mermaid
flowchart TD
    RunData[Run Trace]
    Patch[用户 IR Patch]
    Findings[Validation Findings]
    Review[Review Comments]

    RunData --> Analyze[失败模式分析]
    Patch --> Analyze
    Findings --> Analyze
    Review --> Analyze

    Analyze --> PromptCandidate[Prompt 优化建议]
    Analyze --> MemoryCandidate[Memory Candidate]
    Analyze --> ToolCandidate[Tool 改进建议]
    Analyze --> SchemaCandidate[Schema 改进建议]

    PromptCandidate --> Eval[离线评测]
    MemoryCandidate --> Eval
    ToolCandidate --> Eval
    SchemaCandidate --> Eval

    Eval --> Gate{是否优于基线}
    Gate -- 否 --> Reject[拒绝或继续优化]
    Gate -- 是 --> Human[人工审核]
    Human --> Canary[Canary]
    Canary --> Monitor[质量 / 成本 / 延迟监控]
    Monitor --> Publish[发布新版本]
    Monitor --> Rollback[质量回退时回滚]
```

原则：**学习结果先成为 Candidate，禁止直接修改生产 Prompt、Memory、Tool 或 Schema。**
